# Standard Bank primary research onboarding - 6 October 2026

The owner selected OST as the primary JSE source. The implementation uses OST export history as a bounded read-only source. It covers the 18 registered cash shares and four sector/index ETFs as onboarding candidates. Six actual series are installed and uploaded: Sasol, Naspers, STX40, STXFIN, STXRES and STXIND; the other 16 are WAITING_FOR_EXPORT. Each has 600 retained completed HLCV bars through 5 October. Each lacks all 600 opening prices. Observed HLC inconsistencies remain visible: STX40 6, STXFIN 25, STXRES 56, STXIND 52; Sasol and Naspers 0. None is historical real-data admission.

To onboard more instruments, sign in to Standard Bank OST directly in the Codex browser, visit the authenticated price-history link in the dashboard coverage table, and click **Save To Excel**, or save a CSV of the displayed table. OST's native `.xls` download is an HTML price-history table, which the importer reads directly. In the local dashboard's Trading Strategies tab, expand **Import stock and sector exports**, select files, explicitly map each to its exact instrument and supply the actual SAST capture time. The importer validates the whole batch and saves raw hashes/receipts in ignored local runtime storage. The displayed table has no embedded instrument identifier, so manual mapping is required and remains an identity limitation; filenames are never accepted as proof of identity. A large native file should be imported alone within the 2.5 MB file / 2.7 MB request bounds. No credential or broker session data enters the dashboard. The existing daily collector uploads a bounded v3 snapshot; the normal scheduled worker consumes it. Fresh genuinely acquired exports are needed within four days. Identical source bytes retain their original capture time.

The alternative local CLI reads an ignored JSON manifest with objects `{ "instrument_id": "NPN", "path": "C:/path/to/export.xls", "acquired_at": "2026-10-06T09:00:00+00:00" }` and runs `python scripts/import_ost_exports.py <manifest>`. Native HTML-table `.xls` and CSV use the observed OST columns Date, Closing (c), High (c), Low (c), Volume; an Opening (c) column is accepted only when actually present. Prices convert from cents to rand. Only the latest 600 completed sessions need valid numerical fields; older native history remains outside the bounded research window. Duplicate dates, invalid recent values, wrong headers, future/captured-before-close and stale receipts are rejected. A same-source updated export can advance genuine sessions but repeated bytes cannot change source capture time.

The `GET /api/v1/ost/onboarding` dashboard projection reports 22 candidate instruments, source coverage, missing opens, HLC inconsistencies, expiry and pending gold/USDZAR source contracts. `POST /api/v1/ost/import` is enabled only for same-origin requests to the local launcher on loopback. Hosted web exposes status but rejects import. The batch archive includes raw price exports only; no accounts, positions, cookies or passwords. The primary cutover is conditional on a saved v3 dataset. When active, JSE paper fetch and on-demand opportunity refresh use OST and do not fall back to Yahoo for missing stocks. Old frozen records remain immutable. Gold and USD/ZAR public reference charts remain display-only and do not enter the verified JSE dataset.

The current OST history format omits opening prices, so full OHLC features remain partial until a genuine opening-price source is found. Source adjustment/corporate action, volume and historical availability semantics are still unverified. New historical AI comparisons and model proposals stay blocked. The active scheduled paper worker is not manually forced. There is no automatic broker download service; this requires a supported export/API contract or a supervised browser session. B5 remains PARTIAL_CLOSED.
