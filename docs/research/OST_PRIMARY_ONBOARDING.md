# Standard Bank primary research onboarding - 6 October 2026

The owner selected OST as the primary JSE source. The implementation uses OST export history as a bounded read-only source. It covers the 18 registered cash shares and four sector/index ETFs as onboarding candidates. The existing captured Sasol and STX40 tables are locally installed as the first two series; the other 20 are WAITING_FOR_EXPORT. Sasol has 600 retained completed HLCV bars with 600 missing opens. STX40 has 600, with 600 missing opens and six observed HLC inconsistencies. Both end 5 October. Missing and inconsistent fields remain visible; neither series is historical real-data admission.

To onboard more instruments, sign in to Standard Bank OST directly in the Codex browser, visit the authenticated price-history link in the dashboard coverage table, and save a CSV of the displayed OST history table. In the local dashboard's Trading Strategies tab, expand **Import stock and sector exports**, select one or several files, explicitly map each to its exact instrument and supply the actual SAST capture time. The importer validates the whole batch and saves raw hashes/receipts in ignored local runtime storage. The displayed table has no embedded instrument identifier, so manual mapping is required and remains an identity limitation; filenames are never accepted as proof of identity. No credential or broker session data enters the dashboard. The existing daily collector uploads a bounded v3 snapshot; the normal scheduled worker consumes it. Fresh genuinely acquired exports are needed within four days. Identical source bytes retain their original capture time.

The alternative local CLI reads an ignored JSON manifest with objects `{ "instrument_id": "NPN", "path": "C:/path/to/export.csv", "acquired_at": "2026-10-06T09:00:00+00:00" }` and runs `python scripts/import_ost_exports.py <manifest>`. Files use the observed OST columns Date, Closing (c), High (c), Low (c), Volume; an Opening (c) column is accepted only when actually present. Prices convert from cents to rand. Duplicate dates, invalid values, wrong headers, future/captured-before-close and stale receipts are rejected. A same-source updated export can advance genuine sessions but repeated bytes cannot change source capture time.

The `GET /api/v1/ost/onboarding` dashboard projection reports 22 candidate instruments, source coverage, missing opens, HLC inconsistencies, expiry and pending gold/USDZAR source contracts. `POST /api/v1/ost/import` is enabled only for same-origin requests to the local launcher on loopback. Hosted web exposes status but rejects import. The batch archive includes raw price exports only; no accounts, positions, cookies or passwords. The primary cutover is conditional on a saved v3 dataset. When active, JSE paper fetch and on-demand opportunity refresh use OST and do not fall back to Yahoo for missing stocks. Old frozen records remain immutable. Gold and USD/ZAR public reference charts remain display-only and do not enter the verified JSE dataset.

The current OST history format omits opening prices, so full OHLC features remain partial until a genuine opening-price source is found. Source adjustment/corporate action, volume and historical availability semantics are still unverified. New historical AI comparisons and model proposals stay blocked. The active scheduled paper worker is not manually forced. There is no automatic broker download service; this requires a supported export/API contract or a supervised browser session. B5 remains PARTIAL_CLOSED.
